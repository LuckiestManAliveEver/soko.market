# Conflict policies

All writes pass the existing CP2 domain authorization and deterministic business validators before acceptance. Reward/evaluation scoring is not a replacement for commercial validation. Existing `validateProductInput`, stock validators and contact validators remain the hard gates.

| Domain                 | Policy                       | Exact behavior                                                                                                                                                                                                                                                                                                                                              |
| ---------------------- | ---------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Product create         | Manual on validation failure | Keep local operation; reject attempts three times, then expose a conflict. Never guess a duplicate product match.                                                                                                                                                                                                                                           |
| Product update         | Field merge, then manual     | Three-way comparison against the observed base for name, sku, aliases, unit, quantity, buyingPrice, sellingPrice and fieldValues. A field changed on just one side wins; identical concurrent values are accepted; differing changes to the same field require review. Arrays and fieldValues are atomic fields. Revalidate the merged product through CP2. |
| Inventory counts       | Manual                       | Any changed product base stops the new absolute count. No last-write-wins on stock.                                                                                                                                                                                                                                                                         |
| Customer create        | Manual on validation failure | No cross-device identity guesses or deduplication based on names.                                                                                                                                                                                                                                                                                           |
| Invoices/orders        | Server wins                  | Local snapshots are read-only. Payment or order transitions cannot be queued.                                                                                                                                                                                                                                                                               |
| Runtime pins           | Device authority             | Business sync ignores runtime changes. Only initial installation or explicit swap changes the local pin.                                                                                                                                                                                                                                                    |
| Conversation transport | Existing message identity    | Canonical message IDs and transport deduplication; no modification of business records.                                                                                                                                                                                                                                                                     |

The shared resolver also implements last-write-wins for future noncommercial preferences, but it requires server-assigned sequence numbers. No current commercial domain uses that policy. Client wall clocks never break ties.

Manual review shows local and server versions. Keeping the server version discards all subsequent local edits to that item, and labels the action accordingly. Retrying creates a new immutable operation against the displayed server base, incorporating the latest local state; another intervening server edit can conflict again. The original operation stays in history with the explicit resolution recorded. Sync stops at the first unresolved operation so later operations cannot overtake dependencies.

Transport failures retain the operation and use exponential backoff. Validation failures become a visible dead letter after three failed attempts. A request timeout never authorizes a second write through another provider. Acknowledgements are persisted with the server mutation before the device marks the operation acknowledged. Server restart restoration and lost-ack replay are tested. This follows the repository's single authoritative API-process constraint; multiple independent in-memory API replicas are not supported.
